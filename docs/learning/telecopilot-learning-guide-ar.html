1 المشكلة من ناحية البيزنس

المشروع Agent Assist Copilot لموظفي خدمة العملاء (CSRs) في contact center شركة اتصالات واحدة. الـ AI مش بيرد على العميل بداله، هو بيساعد الموظف يرد أسرع وأدق.

ترتيب الـ Milestones

M0 تنظيمM1 الواجهة + CRMM2 الداتا قبل الموديلاتM3 الموديلات الخمسةM4 التوليدM5 القنواتM6 الـ AgentM7 الصوتM8 MCP والتأمينM9 تقرير Stage AM10 الكلاود

طريقة الشغل

  • كل milestone يبدأ بـ Design pack (رسومات + ERD + شرح القرارات) وإنت بتوافق قبل الكود.
  • بعد كل ticket: الـ agent يكتب تقرير «عملت إيه، وغيرت إيه، وليه».
  • آخر كل sprint: Sprint review ويقف لحد ما تراجع.
  • Definition of Done: tests خضرا + ruff نضيف + docs محدثة + مفيش secrets.
  • ده نفس فكرة Scrum: Epic = Milestone، Story/Task = Ticket.
Local-firstكل حاجة تشتغل على اللابتوب (RTX 2050، 4GB) الأول ونقيس جودتها وأقصى عدد موظفين، بعدين GPUs مجانية، وبعدين بحد أقصى $10.

5 Over-engineering والـ Anti-patterns

Over-engineering = كود أعقد من المشكلة: interface ليها implementation واحدة، طبقات بتعدّي النداء بس، options محدش طلبها، تحسين أداء قبل القياس.

Anti-pattern = حل شائع شكله معقول بس بيعمل مشاكل بعدين:

7 pyproject.toml و pip install -e

pyproject.toml = بطاقة هوية المشروع وملف إعداداته الوحيد (بدل requirements.txt وsetup.py وpytest.ini).

القسمبيعمل إيه
[build-system]إزاي المشروع يتسطب كـ package
[project]الاسم، Python ≥ 3.11، والمكتبات بأرقام ثابتة ==
[project.optional-dependencies]extras: dev (pytest, ruff) وeval (ragas, jupyter)
[tool.pytest] / [tool.ruff]إعدادات الاختبارات والـ lint

ليه pinned versions؟

من غير تثبيت، كل build بينزّل أحدث إصدار، وممكن يكسر الكود فجأة (كان هيجيب cohere 7 وpymupdf 2). مع التثبيت كل build متطابق = reproducible.

pip install -e .

  • . = سطّب المشروع ده (من pyproject).
  • -e = editable: لينك لفولدرك مش نسخة، فأي تعديل يشتغل فورًا.
  • pip install -e ".[dev]" يضيف أدوات التطوير.
  • جوه Docker بنستخدم pip install . من غير -e (نسخة ثابتة).

10 Sync ولا Async

  • Sync: الكود يبعت الاستعلام ويستنى الرد. بسيط.
  • Async: وهو مستني يخدم طلب تاني. أسرع تحت ضغط، بس أعقد.

اخترنا Sync لأن كل الكود sync، وFastAPI بيشغّل الكود الـ sync في thread pool (مجموعة عمال) فالسيرفر مبيقفش، و20–100 موظف حمل صغير. لو الـ load test أثبت إن الداتابيز عنق زجاجة، نحوّل.

تشبيهمطعم فيه كذا جرسون، كل واحد مستني طبقه من المطبخ، وعددهم كفاية للزباين.

11 الإعدادات وCORS وReadiness

Settings (pydantic-settings)

كل القيم اللي كانت مكتوبة جوه الكود اتنقلت لـ settings.py بنفس قيمها، وتتغير من الـ environment أو .env من غير ما نلمس الكود. لو حد كتب provider مش موجود، البرنامج يرفض يشتغل (fail fast).

CORS

المتصفح بيمنع موقع يكلّم API على موقع تاني إلا لو مسموح. قبل الـ POST بيبعت preflight (OPTIONS) يستأذن.

الخيارالمعنى
allow_originsمين مسموحله (كانت * = أي حد، دلوقتي من الـ settings)
allow_credentialsيبعت cookies/تسجيل دخول
allow_methods / allow_headersأنواع الطلبات والـ headers المسموحة
قاعدة أمانallow_credentials=True مع allow_origins=["*"] = ثغرة. دلوقتي الـ origins قائمة محددة.

/api/health و /api/ready

/api/health زي ما هو من v1. /api/ready جديد: بيعمل ping لـ Qdrant وPostgres وRedis ويرجع 200 أو 503 باسم اللي واقع. موجود في api/ مش core/ علشان قاعدة الطبقات.

13 pytest: fixtures وmonkeypatch

  • fixture: تجهيز قبل الـ test: اللي قبل yield قبل، واللي بعده تنضيف.
  • pytest بيدي الـ fixture للـ test بالاسم: لو كتبت parameter اسمه monkeypatch بيبعتهولك تلقائي (dependency injection by name).
  • monkeypatch: يبدّل function أو قيمة مؤقتًا ويرجعها بعد الـ test.
  • autouse=True: الـ fixture يشتغل قبل كل test من غير ما يتطلب.
  • conftest.py: ملف pytest بيقراه تلقائي ويطبق fixtures بتاعته على الفولدر.
  • scope="module": يتعمل مرة واحدة للملف كله.
  • parametrize: نفس الـ test بكذا مدخل.
@pytest.fixture(autouse=True)
def embedded_qdrant(monkeypatch):
    client = QdrantClient(":memory:")          # Qdrant in RAM only
    monkeypatch.setattr(SingletonsManager, "get_qdrant_client",
                        classmethod(lambda cls: client))
    get_vector_repository.cache_clear()        # fresh repository per test
    yield client

علشان كده أي QdrantVectorRepository() في أي test بياخد الـ Qdrant اللي في الذاكرة، ومفيش test يقدر يلمس سيرفر حقيقي.

مثال: اختبار مفتاح Cohere الناقص

def test_missing_api_key_fails_at_construction(monkeypatch):
    with pytest.raises(RuntimeError, match="COHERE_API_KEY"):
        service_with(monkeypatch, None)   # get_cohere_client -> None, then CohereService()

بنمثّل «مفيش مفتاح» ونبني الـ CohereService الحقيقية ونتأكد إنها توقف بخطأ واضح بدل embeddings مزيفة.

uuid5: نفس الـ ID كل مرة

uuid4 عشوائي. uuid5(NAMESPACE_DNS, chunk_id) محسوب من نص ثابت، فنفس الـ chunk ياخد نفس الـ ID دايمًا، وإعادة الفهرسة تستبدل النقطة بدل ما تكررها.

Fake vs Stub

Fake/Stub = بديل لخدمة خارجية بيرجع نتايج ثابتة: من غير إنترنت ولا مفاتيح، سريع ونفس النتيجة كل مرة.

15 BM25 بالتفصيل

ليه hash؟

الـ sparse vector = أرقام (indices) بأوزان. كل كلمة لازم تبقى رقم. بدل قاموس لازم نديره، بنستخدم hash يحول أي كلمة لرقم مباشرة. لازم يكون ثابت: Python hash() كان بيتغير كل تشغيل (الباج)، دلوقتي murmur3 ثابت على كل جهاز.

الـ Preprocessing

"تفعيل eSIM للعميل على باقة WE Mix"
1 tokenize   -> [تفعيل, esim, للعميل, على, باقة, we, mix]
2 stopwords  -> drop "على" (English + Arabic lists)
3 stem       -> Arabic letters: Arabic Snowball | else: English Snowball
4 hash       -> murmur3 -> fixed index per stem
5 weight     -> document: BM25 TF weight | query: 1 per word
6 IDF        -> computed by Qdrant (modifier=IDF)

المعادلة: score = IDF × TF-part

TF-part = tf*(k+1) / (tf + k*(1 - b + b*doc_len/avg_len))     k=1.2, b=0.75
IDF     = log(1 + (N - n + 0.5) / (n + 0.5))                   N = chunks, n = chunks with the word

TF (FastEmbed)

التكرار بيفيد بس بعائد متناقص (k)، والـ chunk الطويل بيتظبط (b). tf=1 ≈ 1.0، tf=5 ≈ 1.8، tf=20 ≈ 2.1

IDF (Qdrant)

الكلمة النادرة أقوى: «customer» ≈ 0.5، «eSIM» ≈ 4.4، «LOS» ≈ 5.6

Query = 1

كل كلمة في السؤال مرة واحدة، فالحساب كله على ناحية المستند

ليه IDF في Qdrant؟

بيتحسب من المجموعة الحية، فيفضل صح لما مستندات تتضاف من غير re-index

تجربة اختيار اللغة

   event: context_ready   (intent, steps, citations)

  • StreamingResponse + text/event-stream، والـ headers بتمنع التخزين المؤقت.

18 Fail fast والـ silent fallbacks

Silent fallback = لما حاجة تفشل، الكود يكمل بحاجة مزيفة من غير ما يقول. ده خطير:

قبل S01-10بعد
Cohere وقع → embeddings مزيفة تتكتب في Qdrantخطأ واضح
Qdrant مش موجود → in-memory بسكوتخطأ واضح
/health يقول HEALTHY و/solve يرد من قايمة كلمات500 و/ready = 503 باسم qdrant

الاستثناء المقبول: خطأ محدد فاهمينه (زي 409 لما عملية تانية عملت الـ collection) نتجاهله، وأي خطأ تاني يطلع.
